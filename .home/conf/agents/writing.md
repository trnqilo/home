
# write clearly

applies to prose: replies, code comments, commit messages, PR descriptions, and docs

+ use plain words: use, help, many, if, is, has
  - avoid delve, crucial, pivotal, showcase, tapestry, landscape, underscore, leverage, utilize, robust, seamless
+ back claims with the mechanism, a measurement, or a source
  - cut vague attributions ("experts say") and trailing -ing clauses ("ensuring...", "highlighting...")
+ write full sentences with articles and verbs
  - spell out arrows and abbreviations
  - one idea per sentence: split anything a reader would have to reread
+ use active voice with a named actor
  - use a stronger verb instead of an adverb
+ be literal
  - no metaphor nouns (substrate, vector, surface, north star, flywheel, machinery), aphorisms, or personified code
+ state points directly
  - no "not just X but Y", forced groups of three, synonym cycling, or "from X to Y" when X and Y aren't on a scale
+ punctuation: no em dashes, use a period or comma
  - colons only before a list or example
  - straight quotes
+ formatting: sentence-case headings, no decorative emoji, bold sparingly, no bullets that open with a bold label and then restate it
+ no openers, closers, or praise ("great question", "I hope this helps", "let me know if")
  - hedge once, and only when you're actually uncertain
  - end on a specific fact or next step, not a summary
